# 随声 · WebRTC 网页对讲机

入口：`https://ichenwin.github.io/intercom/`。纯静态 HTML/CSS/JS，无构建步骤，可直接随本站发布到 GitHub Pages。

## 使用

1. 第一台设备点击「创建频道」，允许麦克风。
2. 复制邀请链接，用第二台设备打开并点击「加入频道」。邀请仅在创建者页面保持打开时有效。
3. 等待显示已连接，按住按钮（或桌面端空格键）说话，松开收听。每个频道限两人，连续发言最多 45 秒。
4. 点击「结束频道」关闭连接并释放麦克风。离开、失去焦点、切到后台均停止发送。

麦克风采集获得权限后保持开启，但音轨默认 disabled，仅在按住且获得频道发言权时 enabled。双方的浏览器可能仍显示麦克风使用指示。频道创建端统一仲裁发言权，避免同时发言。语音使用 WebRTC DTLS-SRTP 加密，本站没有录音或音频存储逻辑。邀请链接等同入场凭据，请私下分享。房间标识在 URL fragment 中，不发送给 Pages HTTP 服务，但会作为 Peer ID 发送给信令服务。

## 网络依赖和限制

- PeerJS 1.5.5 浏览器包已随站点提供，许可证见 `lib/LICENSE.peerjs`。
- 默认使用 PeerJS 公共 PeerServer（`0.peerjs.com:443`）建立信令连接，STUN 使用 Google / Twilio 公共服务，依赖其可用性与当地网络访问条件。
- 默认没有 TURN。某些移动、对称 NAT、企业防火墙网络无法直连。在「连接设置与使用说明」中，双方分别配置自有 TURN 的 URL / 用户名 / 密码，再创建与加入频道。凭据只存当前页面内存，不写入仓库、URL 或浏览器持久存储。中继服务器可看到流量元数据，但 WebRTC 音频仍加密。
- 移动 Safari / Chrome 的后台或锁屏可能挂起页面；请保持前台。浏览器阻止自动播放时点击「点击开启声音」。建议使用耳机避免回声。
- 使用现代 Chrome / Edge / Firefox / Safari，HTTPS（本地开发可用 localhost）。当前实现为双人单频道，不支持后台常驻、多人、离线或来电推送。

## 本地验证

在仓库根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765/intercom/`。两台真实设备需通过 HTTPS 已部署入口测试。
